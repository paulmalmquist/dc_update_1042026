    Platform details & publishing expectations
    This walkthrough reflects the current static-app publishing model described on the existing About page. Applications request named, reviewed, read-only queries through the platform. Exact setup and deployment commands come from the installed Dreamcatcher skills and SDK.
    The current page states that queries execute through a shared platform identity. Confirm what data each app exposes before sharing; do not assume warehouse permissions follow the person viewing it. App visibility and data access require separate validation.
    Python and Flask are shown as extension technologies, not a claim that Dreamcatcher currently hosts arbitrary server processes. This concept page does not deploy an app or connect to live data.
